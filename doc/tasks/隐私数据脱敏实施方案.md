状态: 功能开发、SQLite 和本地回归已完成. `agnes-3.0-flash` 使用 Chat Completions 的最终真实验收为 8/8; 本机隐私用例的 `-race` 验证和组件级浏览器交互验证已通过, MySQL 和 PostgreSQL 仍待实库验证. 性能基准已按用户要求取消. 本文规定具体实现和验证步骤, 验收推翻设计时停止该阶段并报告证据, 不自动换库、扩大范围或修改业务约定.

本文承接 [前期技术方案](隐私数据脱敏.md). 有差异时以本文为准. 实施前完整读取根目录 AGENTS.md, CONTEXT.md 和涉及子目录的 AGENTS.md, 执行 Git 状态及只读差异检查. 保护已暂存, 未提交和未跟踪文件. 修改代码, 下载依赖及运行验证前, 汇报本次范围并获得批准. 最初仅获准编写文档, 后续分阶段授权与执行结果记录在第17节; 真实上游或外部数据库调用仍需单独批准.

## 1. 最终业务与支持边界

采用方案 1, 保留当前 axonhub/llm 协议转换引擎及 SSE fork. 在实际出站 JSON 的选定文本中替换原文, 在最终客户端 JSON/SSE 的选定文本中还原标记. 不在整段 JSON 字节上盲目替换, 不根据用户意图决定处理结果.

占位符固定如下, 不允许运行时修改格式:

```text
source = 13969909666
alias  = PHONE_1
marker = [[OCTOPUS_PII:PHONE_1]]
LEFT   = [[OCTOPUS_PII:
RIGHT  = ]]
```

原文必须是有效 UTF-8, 1-512 bytes, 不 trim, 转小写或归一化. 别名严格满足 `[A-Z0-9_]{1,64}`, 不自动转大写. 两者分别全表唯一, 停用规则仍占用唯一键. 规则允许创建, 列表查看, 修改, 启停和硬删除. 硬删除不保留旧反查或占用, 允许改绑与旧别名复用, 接受历史标记恢复为新值的结果.

功能默认关闭, 新规则默认启用. 对话接口的实际启用条件为功能开关 true 且启用规则至少一条. 停用规则同时退出替换和反查; 不设置独立正向/反向开关. 范围全部关闭时不发生改写, 不产生触发标记. 同一请求固定一份快照, 后台更新仅影响后续新请求.

请求使用第三方 AC 的最左, 同起点最长, 非重叠匹配. 每份实际出站文本只调用一次 matcher, 生成的输出不再参与匹配. 数据库只保证双唯一, 不禁止长短原文包含或交叉重叠.

响应采用全局反查. 只要选定文本中的完整标记存在于当前请求快照中就还原, 不检查它是否由本请求产生. 未知, 非法或残缺标记按字面保留, 还原结果不递归解析. 原请求已有标记不拒绝, 不转义, 不识别用户用途; 它仍按原始输入和规则执行一次机械处理.

四类范围对请求和响应同等生效, 不区分历史和新增. 前端固定名称为普通消息, 工具定义, 工具调用, 工具响应, 默认只选普通消息. 工具调用范围关闭时, 模型返回的工具参数也不还原; 普通消息生成的标记可能被客户端工具直接写入文件. 这是已接受行为.

整个 embedding 和图片生成/编辑/变体请求退出隐私处理, 包括请求, 响应, 错误, JSON 图片 prompt 及 multipart. 对话消息中的媒体, 文件 URL, 二进制不扫描, 独立文字部分继续按范围处理. 推理/thinking/摘要, 协议签名, 加密内容及被签名推理块始终不处理. 不新增媒体协议支持.

协议模型名, 角色, 工具名, ID, 索引, 状态, Header, query, JSON 键及非字符串标量不改. 工具业务 JSON 子树内的字符串值按类别处理, 不用其业务键名或 `_id` 后缀猜测协议字段. annotations/citations, 引用偏移, logprobs 和 usage 不改. 不协调工具 schema, 文件 offset/range 或行列, 不包装客户端工具执行, 不承诺还原长度变化后的定位元数据正确.

不维护命中规则集合, 次数, 会话关联或历史 prompt. 日志正文保持当前策略, 仅新增一个请求级布尔值. 单实例发布一致性是目标, 不增加多实例刷新机制.

## 3. 固定配置与管理契约落点

新增三个 SettingKey, 复用现有运行期设置接口, 无需新增独立配置存储:

| Go 常量 | 数据库 key | 默认字符串及合法值 |
| --- | --- | --- |
| `SettingKeyPrivacyEnabled` | `privacy_enabled` | `false`; 仅 `true/false` |
| `SettingKeyPrivacyScopes` | `privacy_scopes` | `1`; 十进制整数 0-15 |
| `SettingKeyPrivacyFailurePolicy` | `privacy_failure_policy` | `continue`; 仅 `continue/abort` |

Scope 固定为 `Messages=1`, `ToolDefinitions=2`, `ToolCalls=4`, `ToolResponses=8`. 不依赖 JSON 数组顺序或翻译文案作为配置值. 前端展示四个复选开关, 保存时计算位掩码. 未知位, 负数, null 或其他值拒绝. 功能, 范围及失败策略和规则一起发布为请求快照.

管理路由固定挂在 `/api/v1/privacy`, 使用 Auth 后 RequireJSON 的现有顺序. 新增 GET `/list`, POST `/create`, POST `/update`, DELETE `/delete/:id`. 列表按 id 升序返回全部规则, 空列表为空数组. 创建接受 source/alias, enabled 缺省为 true, 显式 false 必须保留, 显式 null 拒绝; 更新要求有效 id 及完整 source/alias/enabled, 不做省略字段的隐式覆盖. DELETE 为硬删除, 不存在返回明确未找到.

HTTP 唯一契约源落在 `doc/typespec/management.tsp` 和新增 `operations/privacy.tsp`, 后者由 `operations.tsp` 导入. agent 先按上述行为建立 `PrivacyRule/PrivacyRuleCreate/PrivacyRuleUpdate` TypeSpec 模型和四个操作, 再让 handler 与前端对齐. 成功沿用 code/message/data 包装和 200, 输入校验 400, 未找到 404, 双唯一冲突 409, 其他内部失败 500; 鉴权与 RequireJSON 保留现有 400/401/415 行为. 文档不维护另一份长期 HTTP 字段表.

固定 op 入口名: `PrivacyRuleList`, `PrivacyRuleCreate`, `PrivacyRuleUpdate`, `PrivacyRuleDelete`, `PrivacyRefresh`, `PrivacySnapshot`, `PrivacySetSetting`. 通用 Setting setter 检测三个隐私 key 后转入 PrivacySetSetting; 隐私事务内不能再回调通用 setter 导致重复加锁. `SettingSetInt` 也转入同一路径. 内部设置加载和备份操作不能跳过 Validate.

唯一冲突, 规则非法, 编译失败, 未找到均使用固定可识别错误. 不把 DB error/panic 原文返回 handler 或日志, 不打印映射. 错误代码识别使用 SQLite UNIQUE/PRIMARYKEY, MySQL 1062, PostgreSQL 23505; 不通过解析含敏感参数的错误字符串匹配冲突. 不全局改变 GORM TranslateError.

## 4. 三库双唯一与确定迁移

实体固定为 `PrivacyRule`, 表 `privacy_rules`, id 为 int 自增主键, source/alias 为二进制字符串值类型, enabled 为 bool 且 NOT NULL/default true, 无 DeletedAt. 两个独立完整唯一索引命名为 `ux_privacy_rules_source` 和 `ux_privacy_rules_alias`.

自定义值类型 `PrivacyBytes` 使用私有 string 持有原文. `String()` 返回业务字符串, `MarshalJSON/UnmarshalJSON` 使用 JSON 字符串, 不出现 base64. 实现 `driver.Valuer` 返回新的原始 `[]byte`, 实现 Scanner 接受 `[]byte` 并复制为 string; 不把 TEXT/string 静默转型. 实现 GormDataType 返回 bytes, GormDBDataType 按驱动和字段 size 返回下面类型, 不实现 GormValue/CAST 第二套绑定逻辑.

| 驱动 | source | alias | 建表机制 |
| --- | --- | --- | --- |
| SQLite | BLOB | BLOB | 006 before 迁移的专用 DDL, 此表不交给 SQLite AutoMigrate |
| MySQL | VARBINARY(512) | VARBINARY(64) | 模型 size/not null/uniqueIndex 加 AutoMigrate |
| PostgreSQL | BYTEA | BYTEA | 模型 not null/uniqueIndex 加 AutoMigrate |

source/alias 查询条件, Updates 和导入统一传 PrivacyBytes/[]byte, 不能传 `.String()` 到数据库比较条件. Go 校验 source 有效 UTF-8 和长度, alias 正则; Scan 后加载仍校验各字段含义. 严格 JSON 字符串解码应拒绝无效 UTF-8, 孤立 surrogate, null 或错误类型, 避免 encoding/json 将非法 Unicode 自动替换后当作用户原值保存.

创建/导入不能直接用带 `default:true` 的实体 bool false 执行 Create, GORM 会将零值替换成默认值. 使用 op 私有 insert struct, enabled 为非 nil `*bool`, 其余字段使用同一二进制类型, TableName 固定; 更新使用 map 显式写 false, 不用忽略零值的 struct Updates. 数据库主键由真实插入返回, 不是 handler 生成.

当前迁移为 1-5, 新增 006 并注册 BeforeAutoMigration. 006 在 SQLite 表不存在时事务内创建表和索引, 其他驱动返回成功并由后续 AutoMigrate 建表. SQLite DDL 固定为:

```sql
CREATE TABLE privacy_rules (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    source BLOB NOT NULL,
    alias BLOB NOT NULL,
    enabled NUMERIC NOT NULL DEFAULT true,
    CONSTRAINT ck_privacy_rules_source_blob CHECK (typeof(source) = 'blob'),
    CONSTRAINT ck_privacy_rules_source_length CHECK (length(source) BETWEEN 1 AND 512),
    CONSTRAINT ck_privacy_rules_alias_blob CHECK (typeof(alias) = 'blob'),
    CONSTRAINT ck_privacy_rules_alias_length CHECK (length(alias) BETWEEN 1 AND 64),
    CONSTRAINT ck_privacy_rules_alias_ascii CHECK (
        instr(alias, X'00') = 0 AND CAST(alias AS TEXT) NOT GLOB '*[^A-Z0-9_]*'
    ),
    CONSTRAINT ck_privacy_rules_enabled CHECK (
        typeof(enabled) = 'integer' AND enabled IN (0, 1)
    )
);
CREATE UNIQUE INDEX ux_privacy_rules_source ON privacy_rules(source);
CREATE UNIQUE INDEX ux_privacy_rules_alias ON privacy_rules(alias);
```

BLOB 的 typeof CHECK 防止 SQLite 把同值分别作为 TEXT/BLOB 存入并绕过唯一性. length(BLOB) 按字节计数. source 可以含合法 UTF-8 中的 NUL, alias 禁止 NUL. SQLite 内置 SQL 不负责完整 UTF-8 判断, 由 Go 严格解码承担.

`db.InitDB` 在任何隐私表 DDL 前执行存在性检查: 已存在时先用静默session完整验证, 不兼容立即停止, 不允许先被AutoMigrate修成另一种结构. SQLite始终从AutoMigrate清单排除PrivacyRule; MySQL/PostgreSQL仅表不存在时加入清单建表, 已存在且验证通过时也从该次清单排除. 新建后和每次启动迁移结束后再次执行 `ValidatePrivacySchema(conn)`, 不能只在首次迁移执行. SQLite 用 PRAGMA table_info/index_list/index_info 和 sqlite_master 核对列类型/非空/默认/主键, CHECK 及两个完整非 partial 唯一索引. MySQL 查 information_schema 核对 VARBINARY 字节长度和完整唯一索引, PostgreSQL 核对 BYTEA 和独立唯一索引. 结构不兼容时固定错误终止启动, 不自动重建或转换未知数据.

现有 migrate.Before/AfterAutoMigrate 会清空注册表, 因而首次/再次启动验收必须用两个独立测试进程, 不在同进程反复调用 InitDB 后宣称迁移重跑通过. 后续该 SQLite 表的变更继续新增版本化迁移.

保留其他模块既有 Debug SQL 行为. 隐私 op 的所有查询/事务固定用 `Session(&gorm.Session{Logger: logger.Discard})`; 包含规则的备份导出/导入和隐私 schema 校验也使用该 session, 防止 Debug 参数或数据库错误输出映射. 不全局关闭 SQL 日志作为无关改动. 不使用摘要索引, 不添加静态加密.

## 5. 快照编译, 发布与备份事务

op 持有一个隐私写锁和 `atomic.Pointer[privacy.Snapshot]`. Snapshot 规则, matcher, markers, restoreMap, 配置和格式均私有且发布后不变. 纯 Go matcher 没有外部资源, 旧快照由请求引用维持, 所有请求释放引用后由 Go GC 回收, 不增加引用计数/finalizer 或 Close matcher 接口.

编译按 source 原始字节稳定排序启用规则, 同序构造 patterns/markers; 不用数据库 id 决定匹配优先级. 空启用规则跳过 matcher 构建. format 常量 LEFT 长14 bytes, RIGHT 长2 bytes, 最大 alias64, 完整标记工程最大80 bytes; 每份快照 L 仍按启用规则中最长可恢复标记计算.

固定第三方调用:

```go
import aho "github.com/petar-dambovaliev/aho-corasick"

builder := aho.NewAhoCorasickBuilder(aho.Opts{
    AsciiCaseInsensitive: false,
    MatchOnlyWholeWords: false,
    MatchKind: aho.LeftMostLongestMatch,
    DFA: true,
})
matcher := builder.Build(patterns)
matches := matcher.FindAll(input)
```

builder/matcher 返回值类型, Build 为指针 receiver, 先保存 builder 再调用. End() 实际是排他字节偏移. 对每个匹配验证 Pattern 范围, `cursor <= Start < End <= len(input)` 和原区间确实等于对应 pattern; 异常返回固定错误, 不自行重选或修正匹配. 用 strings.Builder 顺序写未命中原区间和 marker, 最后写尾部. changed 以最终输出是否不同判定, 不以匹配条数判定. 不使用库 Replacer/全局 Builder pool.

Build/FindAll 可恢复 panic 在组件边界转换为固定 PrivacyError, 不输出 panic 内容. 不声称能从 Go 致命 OOM 恢复. 编译失败保留旧快照, 不能发布空 matcher 继续.

CRUD/配置更新固定顺序:

1. 获得隐私写锁, 从当前快照复制一次管理候选集合, 不逐请求复制.
2. 校验完整候选集合及三个 Setting, 检查双唯一, 编译候选快照.
3. 使用静默 DB session 开事务并写入具体行, 让数据库双唯一负责最终并发防线.
4. Commit 成功后, 在仍持写锁时一次 Store 新快照并同步 Setting 缓存. 新版本号递增.
5. 任一提交前失败回滚, 释放未发布候选, 保留旧版本. 不在提交后再执行可能失败的 matcher 编译.

创建生成的 id 不参与匹配表, Commit 前只补齐候选规则的 id, 不再改变 patterns/Map. 启动 `PrivacyRefresh` 在 settingRefreshCache 之后加载数据库规则, 完整校验编译后发布; HTTP 启动前加载失败则启动失败. 外部直接改数据库不属于热更新入口, 不增加轮询.

DBDump 固定新增 `privacy_rules` 数组, 保留版本1并接受旧版本0/1, 没有该数组的旧备份不删除现有规则. 对完全相同 source/alias 的已有映射幂等跳过, 保留目标 id/enabled; 新映射按备份 id 插入, id 冲突或任一键映射冲突整次失败. 导入不自动重映射 id. 同步 RowsAffected 和 handler wrapper 空集合判断.

导入获得同一写锁, 在整个现有导入事务中合并规则与隐私设置, 对候选数据完成校验/编译, 全部其他表也成功写入后 Commit, 然后一次发布. 三个隐私 Setting 不能沿用不校验的泛型 upsert. 失败回滚所有业务表, 不仅规则. 缺省enabled的新映射采用创建默认true,显式false保留.

PostgreSQL显式ID导入后,在同一事务的业务行写入成功阶段、Commit前修正privacy_rules自增序列. 用 `pg_get_serial_sequence('privacy_rules','id')` 获取实际序列,事务取得该表的 SHARE ROW EXCLUSIVE 锁,将序列设置为 `greatest(coalesce(max(id),0), nextval(sequence))`, is_called=true,确保下次值高于表内最大ID且不倒退. 仅使用数据库返回的regclass参数,不拼接用户提供的标识符. 序列操作错误使业务事务回滚、不发布快照;PostgreSQL序列变化本身不随事务回滚,允许留下递增间隙,不能声称序列也原样回滚. SQLite/MySQL沿用其显式主键插入的序列行为,同样用“导入后正式创建”实测.

导出用同一隐私锁和只读事务取得规则与三个隐私设置的一致版本; 不宣称运行统计/Key 缓存已 flush.

导入提交后的通用 InitCache 不再重复刷新隐私快照, 拆出其他缓存刷新调用, 检查错误不忽略. 其他缓存刷新失败要返回固定的已提交但刷新失败错误, 保留已成功发布的隐私快照, 不谎称数据库回滚. 不顺带重构统计的聚合或保存策略.

## 6. JSON 处理器与字段矩阵

所有协议处理基于 `map[string]json.RawMessage` 和原字段切片的定点更新, 不整体解码成当前 axonhub 结构体再 marshal: 它们不完整表示 raw refusal/原生工具等字段. 未改子树保持原始 JSON, 数字不经过 float64. 修改后的外层 JSON 可以改变空格/键顺序, 未改字段语义和数值必须保留. 处理失败返回原正文, changed=false, 不提交半改写.

四种字段处理形式固定为:

- S: 外层普通字符串解码后按一次文本处理, 重新 JSON 编码.
- J: 已明确为工具业务 JSON 的原生对象/数组, 只递归处理字符串值, 不改键和非字符串标量.
- EJ: 外层字符串明确承载内层 JSON 文档/增量, 外层解码后用内层处理器, 保持内外两次编码关系. 空 arguments 初始值合法; 非空完整文档非法则处理失败.
- D: 工具/schema 的 description walker. 只处理已确认工具描述和 schema 节点的 description; 在 properties/$defs/definitions/patternProperties/dependentSchemas 及 items/additionalProperties/contains/not/if/then/else/allOf/anyOf/oneOf/prefixItems 等子 schema 递归. 不进入 enum/default/const/examples 等实例数据, 也不把业务属性名 description 当作描述字符串.

分类按实际出站/客户端协议位置, 一个字符串只进入一个范围. 已经被转换器渲染为普通消息的工具文字按最终位置归普通消息, 不追溯历史或按工具名猜测. 已知新原生载荷不在本节矩阵且对应范围开启时返回 unsupported_content, 执行失败策略; 非承载字段的未知元数据原样保留, 不能声称全部未知字段都被保护.

## 7. 文本恢复器和工具 JSON 增量

恢复器沿用前期方案的 NORMAL/CANDIDATE 固定语法, NORMAL 以 KMP 跟踪 LEFT 的有效后缀; CANDIDATE 只允许 ASCII alias 和 RIGHT. 先判断完整 marker 命中, 再检查 L. 不完整候选达到 L 后不可能成为本快照的已知标记, 释放字面内容. 失败候选处理当前字节时复用普通前缀匹配, 不重扫整个缓冲.

实现接口为 NewRestorer(snapshot), Push(text), Finish(), HasPending(). Push/Finish 的内部结果含输出和 changed 布尔, 不返回规则 ID 或计数. Finish 幂等, 非流式用 Push 完整文本再 Finish; 空 Map 直接透过. 候选缓冲用 []byte, 摊销增长, 完成或拒绝后复用. 还原输出不再输入解析器. 流结束后销毁整个恢复器.

工具 EJ 增量层必须维护对象/数组语法栈, 期待 key/value 状态, 字符串是否 key, backslash, `\uXXXX` 与 surrogate pair 状态. 只有解码后的字符串值进入 Restorer, JSON key 原样保留; 两个业务字符串值不能串成一个 marker. 每个字符串结束先 Finish 后编码, 不能把还原字符串中的引号/换行变成 JSON 结构.

未知标记不递归, `\u005b` 解码为 `[` 后应能匹配 LEFT, 分割的 UTF-8/escape/surrogate pair 需要缓存到可解码时. 不逐片调用 json.Unmarshal 完整参数. 最大嵌套深度128, 超出进入失败策略; 不增加 schema 业务验证或补括号/补引号修复.

对空 initial input `{}` 和完整 done 快照单独处理, 不加入 delta 词法流. custom_tool_call.input 是 S 增量, 不共用 function EJ 语法. 正常 EOF/错误可以释放原始字面尾部, 但非法完整工具 JSON不能被补全并伪装合法工具调用.

## 8. SSE 身份, 事件矩阵和固定 FIFO 算法

处理器输入为现有 decoder 输出的 `httpclient.StreamEvent`, 保留 Type, LastEventID, Headers, CleanEOFCompletionEvidence 及 Data 语义. 不重写底层 SSE framing, 不把 TCP 分块等同于逻辑 delta.

### 8.1 客户端事件

| 协议 | 增量路径与逻辑键 | 完整快照/终止 |
| --- | --- | --- |
| Chat | delta.content/refusal: `(choice.index, field)`; delta.tool_calls[*].function.arguments: `(choice.index, tool.index, arguments)` | message 独立快照; finish_reason 先处理同 chunk 最后 delta 再结束 choice; DONE 结束全流 |
| Responses | output_text/refusal.delta: `(item身份, content_index, field)`; function_call_arguments.delta: `(item身份, arguments)` EJ; custom_tool_call_input.delta: `(item身份, input)` S | 对应 done, content_part.done, output_item.done, completed/failed/incomplete/cancelled 的完整快照独立处理 |
| Anthropic | `(message.id, block.index, text/input)`; text_delta.text S; input_json_delta.partial_json EJ | start 内初始内容独立处理; content_block_stop 结束 block, message_stop 结束全流 |

Chat tool.id 后到时与同 choice/tool.index 建立别名, 不将不同 choice 的工具合并. index0合法, 缺 index 不能变成0. usage-only chunk 不结束文本. DONE 非 JSON sentinel 原样通过; reasoning delta 不处理.

Responses 建立 `output_index <-> item.id <-> item_id` 和 item.id/call_id 关联, call_id 不是 item_id. created/in_progress/queued 建立 response.id, output_item.added 建立 item 及 initial payload, content_part.added 建立 content 身份. 必须区分字段缺失和0. 对直接给 output_index 的 delta 使用该稳定键, 后到 id 只补别名, 不迁移/重置状态. 关联矛盾返回 stream_identity 错误.

明确支持 raw `response.refusal.delta/done`, done 字段 refusal, 不能靠 pin 的缺字段结构体整体 marshal. output_text.done/text, function_call_arguments.done/arguments, custom_tool_call_input.done/input, content_part.done/part, output_item.done/item 和 terminal.response 各自完整恢复一次, 不追加到 delta. metadata 事件原样保留. error 恢复选定 message 后保持错误, reasoning/image_generation 事件不扫描载荷. 当前转换器可能以 completed event 携带 cancelled status, 隐私层保留实际组合, 不纠正协议生成器.

Anthropic message_start.message.content 与 content_block_start.content_block 可能含非空 text, 初始 tool input 和原生工具结果, 均完整分类处理. start 中空 input 不拼入 partial_json. 后续 delta 必须查已建立 block 类别; thinking/signature/citations delta 保持原样. message_delta usage/stop 字段不改, ping 保留原顺序. 不新增 text/input done 快照.

### 8.2 原事件字段分配与保序

采用原事件保留, 字段片段重分配, 全局 FIFO. 不新增事件, 不修改 ID/sequence_number, 不删除变空的 delta 事件:

1. 每个事件保留原始 Data 不可变副本和候选字段版本. 所有输入事件进入同一有序队列, 包括 heartbeat/usage/推理事件.
2. 每个待处理字段的字节/解码 token 记录所属事件和字段位置. LEFT 未完成或工具 JSON escape 未完成时, 相关事件标为未决, 不写出候选片段.
3. 普通无未决文本立即提交. marker 跨事件完成时, 替换文本写到 marker 起点所属字段; 被消费的后续片段从各自字段移除, 字段可以为空字符串. 字面回退同样按原片段归属返回.
4. 每个事件可有多个 choice/工具字段, 所有未决引用解除后才可提交. 只从 FIFO 队首释放连续已完成事件, 不让其他流/心跳越过未决队首.
5. done/stop/error 到达时, 先结束对应增量状态并释放字面尾部, 再独立处理该事件内完整快照. 每个原事件只发一次.
6. 正常 EOF 结束全部未决流, 释放字面文本; 取消直接清理队列不补发. 不生成 finish/DONE/message_stop/completed.

已结束逻辑流在所属choice/item/block终止后释放恢复器,片段和身份别名;最终完整快照通过自身payload分类,不保留旧增量缓冲等待快照. MaxLogicalStreams约束活跃逻辑流,已退休身份的late delta视为stream_identity错误,不能隐式重开.

内层 JSON 的延迟 escape/token 携带所属片段位置. 对还原业务字符串使用内层 JSON escape 后写回 partial_json/arguments 片段, 再做外层 escape. 不把一个还原结果拆成含未转义原文的片段. 不跨 JSON value 迁移输出. strict FIFO 会让某个候选暂时阻塞其他流和心跳, 这是保序代价, 不增加隐私等待超时.

固定工程保护常量:

```text
MaxPendingEvents  = 1024
MaxPendingBytes   = 8 * 1024 * 1024
MaxLogicalStreams = 1024
MaxJSONDepth      = 128
```

待定字节统计包括保留原事件, 候选序列化结果, 片段/escape 缓冲和身份字符串; 不只统计 marker. 插入前计算上限, 刚好等于允许, 超出触发 resource_limit. 不改 axonhub 现有单事件限制. 原有日志 responseEvents 的全流缓存仍可能随响应增长, 不宣称整个请求内存有界.

继续模式遇到隐私错误/资源上限: 放弃当前全部未提交改写, 按原事件 FIFO 释放保留 Data, 然后该响应余下永久透过, 不重新开启恢复. 已写内容不回滚. 当前错误事件也只能提交原始完整外层事件. 外层 JSON 非法或无法保持协议合法则终止, 不发送拼坏数据. 日志布尔仅记录实际提交过的修改.

## 9. relay 接入, 失败分类和 usage

Handler 入口先根据 inboundType/RequestType 建立排除信息和请求快照, 通过同一引用传入分组与指定渠道构造. parse 错误需要写回时也用入口快照. 不移动或改写 APIKeyAuth. 不能通过每 attempt 或每 SSE chunk 获取 Setting 改变版本.

`OnOutboundRawRequest` 中先完整 `applyRequestOptions`, 再按实际 outbound APIFormat 处理正文. Doubao 按 Chat 选择器, 不根据 URL 后缀猜协议. 每次 retry 从未改过的内部原请求重新转换, 不修改 internalRequest/RawRequest 来保存替换结果. 保留本次选项应用后的原 Body, 完整成功后才替换 Body.

非流式在 forward 的最终 result.Response.Body 写回前恢复. 指定渠道 TransformError 后同样恢复, 本地 parse/最终错误统一使用入口快照. SSE 在日志缓存/Render/Flush 前经过 StreamRestorer, 只缓存实际将提交的事件. passthrough 原请求/响应/事件仍走这些公共边界, 不额外叠加第二次扫描. 原生 Responses/Anthropic raw 回放也在最终 Body 上处理.

改写正文后删除旧 Content-Length 并由 HTTP writer/client 按新 Body 建立长度. 未改 Headers 的业务含义保持, 不干预自定义认证 Header 覆盖顺序. 已知无变化直接返回原 body/事件, 不无意义重新编码.

失败策略 continue 为默认, abort 可配置. continue 请求侧放弃整个本次 JSON 改写, 发送选项应用后的原 Body; continue 非流式响应放弃该 Body 恢复; continue SSE 按第8节单向切换透过. 身份/JSON能力错误都采用同一规则, 固定日志说明隐私处理未完成, 不打印敏感文本. 原生鉴权, 协议转换及上游网络错误不能由 continue 掩盖.

abort 请求侧不发送上游, 不换渠道绕过, 返回固定502及隐私处理失败信息. 非流式未写回时返回固定502, 如果已有真实 usage 仍保存真实用量. SSE 已写回时关闭上游/连接并记录失败, 不尝试改 HTTP 状态码或伪造完成事件, 不重试.

固定类型 PrivacyError 包含 compile, invalid_json, unsupported_content, match, stream_identity, resource_limit 类别. relay 在渠道失败副作用前识别本地隐私错误, 不当作上游 HTTP 状态更新 Key 冷却或渠道熔断. 当前 attempt 可记录 skipped/local privacy failure, 最终请求记录失败; 上游成功执行后的 usage/cost 仍归实际渠道, 不增加渠道失败计数来伪装上游异常. 客户端取消使用现有 errClientDisconnected 边界, 不返回 nil 当作成功.

计费保持真实上游usage,不按还原文本估算. 为隐私处理的对话请求增加每attempt的RawUsageCapture,在 `OnOutboundRawResponse` 从实际出站响应Body读取usage存在性,在 `OnOutboundRawStream` 包装原上游Stream,只观察原Data,返回原事件不改字节. 此位置在outbound协议转换之前. 快照和capture活到stream.Close, `OnProcessEnd` 不提前清理. stream读取协程更新capture,保存阶段读它时使用mutex保护,不让并发取消造成数据竞争.

RawUsageCapture只用于计费观测,不参与文本恢复,不在普通日志额外增加统计字段. Capture只保留usage字段及presence,不缓存原始上游全文. Chat/Doubao读取顶层usage,Responses读取response.usage或完整JSON顶层usage,Gemini读取usageMetadata,Anthropic合并message_start.message.usage的input/cache字段与message_delta.usage的最终output. 对累计字段以最后明确出现值覆盖,不逐事件相加,缺失和真实0分开. 按现有适配器语义转换为llm.Usage: Chat/Responses/Gemini保留原prompt/input/output及cache细节,Anthropic统一prompt含input+cache_read+cache_creation,既有价格算法不变. 非流式JSON和原流式终态存在usage才计入,无usage不从文字补造.

原有OnOutboundLlmResponse和最终聚合不再对这些对话attempt独立更新第二份计费值,以capture统一落点;排除的embedding/image继续原usage路径. 保留stream.EnsureUsage,其当前实现只要求上游include_usage,不移除其请求兼容行为. 客户端事件聚合只负责实际写回的日志Body,不能把转换后的usage当作原始证据. continue/abort/取消如果已捕获usage也保存,未收到不补造. 最终真实执行的渠道和Key费用只落一次,真实上游错误与本地隐私错误仍分开归因.

```text
  -> tee原始上游JSON/SSE C
  -> 客户端协议转换 -> 隐私恢复
  -> 实际客户端收到 D -> 日志及usage差值
```

观测代理不生成/改写响应. 使用ReverseProxy兼容实际上游路径,tee请求Body后重建Body和ContentLength,复制原始响应body/SSE同时立即转发,不能等完整流结束才交给relay. 专用Transport禁用环境代理,禁用重定向和透明重试,不把Key返回客户端. 代理原子计数限制8次,相同case第二次及第9次在外发前fail.

代理在真正外发前按每行配置校验B:TextDisabled两行要求隐私层不改写且原文保留;TextEnabled和ToolCall各行按开启范围检查最终有效文本的一次替换期望,ToolCallDisabled只关闭工具调用范围,其普通消息仍应替换. 每行都核对排除字段、实际模型和认证配置不被隐私层改动. 不把“所有行不得含原文”套到关闭基线,也不检查schema约束中的主动排除值必须消失. 报告只写case/格式/模型/哈希/布尔断言/usage,不输出Key/完整Header/敏感URL. 如需保留合成Body证据仅置于t.TempDir;默认不上传或写仓库. 取消时context关闭代理到真实上游的连接并等待测试goroutine结束.

真实测试4份证据分别判定:

- B违反字段替换/排除规则:实现错误,阻断该次外发.
- C含已知完整marker但D在开启范围中未恢复:恢复/转换/调度错误.
- C改写/遗漏/截断marker或拒绝回显,D符合机械规则:模型行为,严格往返用例fail为MODEL_MARKER_NOT_PRESERVED,不能算系统通过或skip.
- C无marker而D凭空新增原文/重复:调查实现路径,不能说是全局恢复正常结果.
- D合法但工具schema/offset不能使用:已接受业务限制,不偷偷删除元数据或改数值来让测试过.

usage从C的原生终态独立读取:Chat prompt_tokens/completion_tokens,Responses input_tokens/output_tokens,Anthropic input/cache读写/output按当前适配器统一语义核对. 不逐事件累加累计usage,不按正文重算,不要求开/关两次真实调用token数相等. 比较客户端usage,StatsAPIKey/StatsChannel/StatsTotal请求前后差值和实际持久化RelayLog,确认只计一次. 上游缺usage时usage验收fail,不补造;成本仅核对本地价格计算,不宣称供应商账单一致.

真实网络或模型失败的结果与Mock明确分开. 报告可以写出站通过但模型标记保持失败,不能将其汇总成真实往返通过.
