# 技术方案 - 隐私数据脱敏

状态: 实施设计已定稿, 尚未实施. 最终业务行为, 固定技术实现及分阶段验证步骤见 [隐私数据脱敏实施方案](隐私数据脱敏实施方案.md). 本文保留前期技术论证和候选设计, 后续定稿以实施方案为准. 本轮仅更新文档, 尚未修改业务代码, 安装依赖或执行测试; 设计选择和实际验收结果分别记录.

## 1. 目标与已确认决策

管理员在后台配置原文与别名的一一对应关系. Octopus 在实际请求发给上游前, 将指定文本字段中的原文替换为完整占位符; 在上游响应转换为客户端协议后, 将完整占位符还原为原文.

请求方向采用第三方 Aho-Corasick (AC) 自动机, 对每份待处理文本进行一次多模式匹配和替换. 响应方向采用固定格式占位符的增量状态机与共享反查 Map. 非流式响应一次输入完整文本; SSE 响应持续输入同一逻辑文本流的增量.

反向还原采用全局词库. 只要完整占位符存在于本请求持有的全局反查快照中, 就执行还原. 不记录本请求命中的规则 ID, 不收集命中集合, 不维护会话关联或历史 prompt 状态. 使用 `previous_response_id` 的增量请求也按同一规则还原, 无需补记前一轮的命中情况.

规则表, 编译后的 AC, 反查 Map, 占位符格式与最大长度在更新时一起发布为不可变快照. 每个转发请求持有快照引用, 请求过程中不切换版本. 请求级快照只负责一致性, 不限制全局还原范围.

本方案保持既有分组路由, 指定渠道直连, 受限 API Key 校验, 重试, 熔断和计费规则. 不引入新的协议转换引擎, 不自行实现 AC 算法内核, 不使用独立隐私代理进程.

## 2. 数据模型与占位符格式

建议新增独立的规则表, 模型及表名在实施前确定. 不将整份映射塞进单个 Setting JSON 值, 以便数据库约束每条规则的一一对应关系, 并支持单条管理和明确的冲突提示.

后台只需配置原文和中间别名. 完整占位符由程序统一包装. 以下是候选格式, 尚未固定为最终接口约定:

```text
原文: 13969909666
别名: PHONE_1
完整占位符: [[OCTOPUS_PII:PHONE_1]]

LEFT  = [[OCTOPUS_PII:
RIGHT = ]]
```

保留专用前缀可以降低与普通文字, JSON 或程序常量冲突的概率, 但无法证明原文一定不含这个前缀. 原请求中已经含有保留标记时, 是拒绝, 转义还是允许字面使用, 需要单独确定.

建议的持久化字段如下. 该表描述数据实体, 不定义 HTTP 请求或响应契约.

| 字段 | 用途 | 约束 |
| --- | --- | --- |
| `id` | 规则主键 | 使用项目现有主键惯例 |
| `source` | 需要替换的原文 | 非空, 独立唯一 |
| `alias` | 用户配置的中间别名 | 非空, 独立唯一, 满足最终字符集与长度限制 |
| `enabled` | 是否参与正向替换 | 建议字段, 停用是否影响反向还原待确认 |

全局词库需要两个独立唯一约束:

```text
UNIQUE(source)
UNIQUE(alias)
```

单个 `UNIQUE(source, alias)` 只禁止重复整对, 仍会允许一个原文对应多个别名, 或多个原文对应同一别名. 在统一且无歧义的包装格式下, 别名唯一即可保证完整占位符唯一.

原文保持用户输入的实际内容, 不自动 trim, 转小写或做 Unicode 归一化. 校验拒绝空字符串和无效 UTF-8. 别名建议限制为大写 ASCII 字母, 数字和下划线, 并禁止分隔符进入别名. 字符集, 最大原文长度和最大别名长度属于待确认参数.

Go 字符串的精确比较应与数据库唯一约束一致. 实施时核对 SQLite, MySQL 和 PostgreSQL 的大小写, 重音, 尾随空格及索引长度行为. 不直接复制默认字符串唯一标签就宣称三库字节精确一致, 也不擅自将既有某处 `varchar(191)` 的长度作为本功能上限. 如使用摘要索引规避长文本索引限制, 需要明确碰撞处理, 且摘要不能作为原文加密.

## 3. 规则快照与更新

快照在概念上包含以下数据:

```text
RuleSnapshot:
    version
    forwardMatcher       // 正向 AC 与对应替换值
    restoreMap           // 全局完整占位符 -> 原文
    leftPrefix
    rightSuffix
    prefixTable          // 固定左前缀的 KMP 前缀表
    maxPlaceholderBytes  // L
```

`L` 按反查 Map 中可还原的完整占位符计算, 使用字节长度. 固定 ASCII 别名格式使字节长度与标记字符数量一致. 若反查 Map 为空, 响应恢复器直接透过文本, 无需等待占位符前缀. 停用规则是否保留在反查 Map 中, 在规则生命周期决策后确定.

op 管理启动加载, CRUD 和备份导入后的快照生命周期. AC 封装和文本恢复器放在一个小型独立包中, 不反向依赖 op, db 或 server. op 负责读取实体并编译, relay 读取快照, 避免引入依赖环.

单进程写路径串行化. 候选规则集合先进行完整校验和编译, 数据库事务提交成功后, 一次替换内存快照指针. 校验, 编译或事务失败时保留原有效快照, 不发布半套新规则. 不能从正在逐条更新的通用分片缓存中构造一个声称原子的全表快照.

同一请求在分组路由或指定渠道直连的构造分支中都持有同一份快照. 即使后台增删规则导致 `L` 缩短, 已经开始的响应仍使用旧格式, 旧 Map 和旧 `L`. 新请求使用新快照. 不为每个请求复制整份词库.

规则即时落库, 无需另加退出时保存规则的机制. 快照和流状态的存活周期必须分开: pipeline 返回一个流对象时, 客户端可能尚未开始消费; 恢复器资源要保持到流结束, 取消或 `Close()`.

该方案保证单进程内发布一致性. 多实例间的规则刷新需要另定广播或轮询机制, 内存原子指针无法自动同步其他实例.

## 4. 请求方向: 对最终出站内容做 AC 替换

处理顺序为:

```text
客户端 JSON
    -> 鉴权与入站解析
    -> 分组路由或指定渠道直连
    -> 出站协议转换
    -> 应用分组和渠道请求选项
    -> 隐私文本替换
    -> 上游 HTTP 执行
```

脱敏必须覆盖最终实际发出的内容. 当前 `internal/relay/relay.go` 的 `relayPipelineMiddleware.OnOutboundRawRequest` 会调用 `applyRequestOptions`, 应在请求选项完成后接入处理, 避免渠道覆盖参数重新注入未脱敏内容.

先识别实际出站协议中的受保护字段, 解码字符串值, 对原字符串进行 AC 多模式替换, 再正确编码回请求. 不直接在整段 JSON 字节上盲目替换, 不修改键名, 模型名, ID, 认证 Header, 签名或二进制数据.

同起点的重叠原文建议采用最左且最长匹配, 替换结果不重叠. 替换只扫描原输入, 生成的完整占位符不再次进入匹配. 例如长手机号和其短前缀都在词库中时, 不先替换短前缀而破坏完整值.

单次扫描指每份最终出站文本扫描一次. 一次客户端请求如果发生渠道重试, 可能生成另一份协议或请求选项不同的最终请求, 需要对该请求再执行一次处理. 各次尝试从独立的出站内容生成结果, 不把上一尝试已替换的结果再次替换, 也不改变选路前保存的原始请求.

请求处理失败时不得回退发送原文. 输入不合法, 受保护内容无法正确处理或内部编译异常应返回明确错误, 保持已有鉴权边界. 非 JSON 请求及 multipart 文本字段的保护范围尚未确定, 实施前必须明确阻止, 提示或适配策略, 不静默声称已经保护.

## 5. 响应方向: 固定格式增量恢复器

处理位置在上游响应转换为客户端协议之后, 实际写回客户端之前. 非流式 JSON 和 SSE 使用同一套反查规则. 指定渠道直连的错误响应另有直接写回分支, 也应接入相同的内容处理边界, 避免只覆盖正常成功响应.

恢复器只查询共享反查 Map. 不判断标记是否曾在本请求命中, 不维护会话权限集合. 已登记完整标记出现时还原, 未知或不完整标记按既定结束策略原样保留. 全局还原也意味着模型生成一个并未由当前请求替换出来的已登记标记时, 仍会得到对应原文; 这是已选择的功能行为.

固定格式允许恢复器维护普通文字和候选占位符两类状态. 普通文字状态用 KMP 识别可能跨片段的左前缀, 只保留仍可能组成左前缀的后缀. 候选状态逐字节检查别名字符, 右后缀和长度, 不重新扫描整个候选.

完整右后缀到齐时直接查 Map. 格式不合法时立即释放不能还原的文字并恢复前缀识别. 先判断是否完成合法标记, 再判断长度上限; 候选达到 `L` 仍未完成时, 后续不可能补成本快照中的已登记标记.

`L` 是空间上限, 不限制等待时间. 如果上游停在半个标记后不再发送文本, 候选会等待流结束或取消. 是否增加恢复器等待或空闲超时属于额外决策, 不擅自改变现有首事件超时与重试行为.

以下为核心文本算法伪代码. `emit` 只写当前输出缓冲. 实际实现使用 `[]byte` 或 Builder, 不采用不可变字符串逐字节拼接. 示例分隔符分别以 `[` 和 `]` 开始, 合法别名不含这些字符, 使候选失败时只需重新识别当前字节.

```text
Restorer(snapshot):
    LEFT = snapshot.leftPrefix
    RIGHT = snapshot.rightSuffix
    L = snapshot.maxPlaceholderBytes
    restoreMap = snapshot.restoreMap
    prefixTable = snapshot.prefixTable

    state = NORMAL
    leftMatched = 0
    candidate = emptyBuffer
    identifierLength = 0
    rightMatched = 0
    finished = false

push(text):
    require not finished
    if restoreMap is empty:
        return text

    for byte in text:
        if state == NORMAL:
            consumeNormal(byte)
        else:
            consumeCandidate(byte)
    return takeOutput()

consumeNormal(byte):
    while leftMatched > 0 and byte != LEFT[leftMatched]:
        fallback = prefixTable[leftMatched - 1]
        emit(LEFT[0 : leftMatched - fallback])
        leftMatched = fallback

    if byte == LEFT[leftMatched]:
        leftMatched += 1
        if leftMatched == length(LEFT):
            candidate.append(LEFT)
            leftMatched = 0
            state = CANDIDATE
    else:
        emit(byte)

consumeCandidate(byte):
    if rightMatched == 0:
        if byte is a valid identifier byte:
            candidate.append(byte)
            identifierLength += 1
        else if byte == RIGHT[0] and identifierLength > 0:
            candidate.append(byte)
            rightMatched = 1
        else:
            rejectCandidate(byte)
            return
    else:
        if byte != RIGHT[rightMatched]:
            rejectCandidate(byte)
            return
        candidate.append(byte)
        rightMatched += 1

    if rightMatched == length(RIGHT):
        if restoreMap contains candidate:
            emit(restoreMap[candidate])
        else:
            emit(candidate)
        resetCandidate()
        return

    if length(candidate) >= L:
        emit(candidate)
        resetCandidate()

rejectCandidate(byte):
    emit(candidate)
    resetCandidate()
    consumeNormal(byte)

resetCandidate():
    candidate.clear()
    identifierLength = 0
    rightMatched = 0
    state = NORMAL

finish():
    if finished:
        return emptyText
    finished = true
    if state == CANDIDATE:
        emit(candidate)
    else if leftMatched > 0:
        emit(LEFT[0 : leftMatched])
    clearParserState()
    return takeOutput()
```

非流式文本使用新恢复器一次 `push` 完整内容, 再执行 `finish`. 输出的原文不重新送入解析器, 防止递归还原. 候选失败时复用有界缓冲, 流结束后再释放恢复器, 不在每个片段中反复申请和销毁内存.

## 6. SSE 与协议接入边界

新增层接收 axonhub decoder 已组装好的 SSE 事件, 不重写 HTTP 分片或底层 SSE framing. 对事件 JSON 解码后的文本字段做恢复, 再编码回事件. JSON 的键, 数字和未修改内容应保持语义, 不能因通用浮点解码改变大整数等协议值.

每个逻辑文本流分别保存恢复器. OpenAI Chat 按实际 choice index, 字段类型及工具调用 index/ID 区分; Responses 按 item, output, content 标识区分; Anthropic 按 content block index 与 delta 类型区分. 不能把正文, 推理和不同工具参数拼入同一个候选, 也不能仅按 JSON 数组位置或全文出现的第一个 index 猜测身份.

增量事件延续状态. `output_text.done`, `response.completed` 等完整文本快照独立还原, 不追加到增量缓冲中, 避免重复输出. 工具参数需要识别内层 JSON 字符串及转义状态; 不完整的参数片段不能逐块当作完整 JSON 解析. 原文含引号, 反斜杠或换行时, 按内层和外层编码关系正确写回. 普通文本恢复器不直接承担工具 JSON 解析职责.

事件顺序, event type, ID 和 sequence number 必须保持合法. 待定尾部的输出要安排在所属逻辑流的终止事件之前. 不能为了补发尾巴随意重复 `sequence_number` 或拼出不属于该工具调用的 delta. 心跳等非文本事件按协议允许的方式通过; 事件输出调度与文本解析状态分开管理.

正常结束, 上游异常和客户端取消分别处理. 正常结束保留尚未完成的字面文字, 不猜测缺失编号或右后缀. 上游异常不能被伪装成成功完成; 是否在错误事件前释放字面尾部, 需要根据协议和当前写回状态确定. 客户端取消时关闭上游流并释放状态, 不再向已断开的连接补发文字.

已写回内容无法收回, 也不能通过重新请求覆盖. 保留 relay 现有的写回后停止重试边界. 前缀缓存带来的客户端文本等待与上游首事件等待是不同指标, 不能把过滤前收到的角色或元数据直接当作过滤后的可见首字.

Header, 模型名, 角色, 各类 ID, 签名, 加密内容及二进制不按普通文本处理. 带签名的 thinking 内容需要连同下一轮回传语义核对, 不能仅保留签名字段却任意改写被签名文字. 引用或标注的偏移会因还原长度变化而失效, 应换算或明确限制支持, 不静默保留错位索引.

计费与 usage 保持上游返回的真实值, 不按还原后的文字重新计算 token.

## 7. 协议直通, 日志与规则生命周期

协议直通当前直接使用原始请求和 SSE 内容. 仅在统一 `llm.Request` 上处理会被原始转发路径绕过, 所以过滤必须覆盖实际出站和实际写回边界. 启用隐私改写后是否继续使用协议直通优化, 尚需确认; 如继续使用, 必须明确其文本改写行为, 并同步核对 `CONTEXT.md` 中的既有定义. 指定渠道直连仍是单次目标尝试, 不能因隐私处理变成其他路由方式.

当前 `RelayMetrics` 保存原请求与最终响应正文, SSE 正常结束后还会聚合事件用于日志. 仅在网络出口替换无法保证日志没有原文. 日志正文是否再次脱敏, 是否保持管理员可读原文, 尚未决定. 新规则管理日志应只记规则 ID, 版本或配置动作, 不打印整份映射或将原文放进 URL. 唯一冲突返回固定业务消息, 避免数据库错误把敏感原值带到日志或浏览器 console.

规则表, 后台管理响应和 JSON 备份需要保存可恢复的原文. 本方案不提供静态存储加密, 不声称消除数据库或备份中的明文数据, 也不清理已有日志. 是否为规则原文增加加密存储属于额外需求.

全局还原减少了会话管理, 但要求规则的含义稳定. 删除映射后, 后续请求中的旧标记将无法还原. 若同一标记重新绑定到另一个原文, 上游历史中的旧标记可能被还原成新值. 建议避免复用旧标记, 但系统如何强制保留占用, 是软删除, 历史反查还是标记带稳定 ID, 需要先确定.

停用正向替换但保留反向映射可继续还原旧历史, 不需要保存会话. 完全删除则更彻底地移除词库原文, 同时失去旧标记的恢复能力. 本文不擅自选择其中一种. 原文或别名的更新也需要与这些生命周期规则统一, 不能简单覆盖后就保证历史内容正确.

## 8. 管理, 数据迁移与实现范围

管理请求沿用 `handler -> op -> db` 和现有管理 JWT 鉴权. 后台建议在设置面板提供规则列表和编辑入口, 使用独立 endpoint 与 TanStack Query 缓存; 不因 UI 放在设置页就把规则实体塞入 Setting 表. 总开关, 默认状态和逐条停用功能在实施前确认.

纯新增表和普通索引优先使用模型标签与 AutoMigrate, 并将实体加入 `internal/db/db.go` 的显式清单. 仅在数据库专用比较属性, 旧数据转换或兼容性要求需要时增加递增的显式迁移, 不为新增表强造版本迁移, 不改已发布迁移.

备份涉及 `internal/model/backup.go`, `internal/op/backup.go` 及导入后的缓存刷新. 新实体需要显式纳入导出, 导入和结果统计. 相同映射可按幂等导入处理; 两个唯一键分别冲突时应报告并回滚, 不机械沿用忽略冲突或按一个键 upsert 的行为. 导入后快照编译或刷新失败不能继续报告功能更新成功.

拟影响的代码按职责划分:

- `internal/model/`, `internal/db/`: 新规则实体, 自动迁移和必要兼容处理.
- `internal/op/`: CRUD, 启动加载, 编译发布, 备份导入导出.
- 独立隐私处理包: 第三方 AC 封装, 快照数据, 文本恢复状态机和协议字段处理.
- `internal/relay/relay.go`, `direct_channel.go`, `passthrough.go`, `type.go`, `metrics.go`: 请求快照, 出站处理, 非流式与 SSE 回写, 错误和日志边界.
- `internal/server/handlers/`, `web/src/api/endpoints/`, `web/src/components/modules/setting/`: 管理接口与后台配置.

实施时同步 TypeSpec 的管理模型, 操作和必要协议说明, 由 emitter 生成 `doc/openapi.yaml`, 不手改生成 YAML. 数据实体说明同步 `doc/ENTITY.dbml`. 本技术方案不另行维护一套精确 HTTP 字段表.

## 9. 第三方选型与开源参考

请求匹配首选候选为 `github.com/wasilibs/go-aho-corasick v0.6.0`. 它包装 Rust `aho-corasick`, 默认通过嵌入 WASM 和纯 Go 的 wazero 运行, 不要求 cgo. 已只读核验其最左最长匹配及非递归替换能力; 尚未进行项目兼容性或性能测试. 默认后端对共享 matcher 调用加锁, 需要核对并发开销, 输入复制, 匹配列表, 热更新资源释放及各发布架构兼容性. 许可证和嵌入依赖声明也需要在选型验收时核对.

纯 Go 的 `petar-dambovaliev/aho-corasick` 可作为备选. 调研发现其重叠区间与内置 replacer 的组合需要进一步校验, 不直接套用默认替换器. 任何替换库都应通过重叠, Unicode, 无匹配及重复命中验证后再确定版本, 不凭库名或 star 数承诺吞吐.

AC 算法本身支持保留状态的流式匹配. Rust 官方流式 API 当前支持 Standard 匹配, 最左最长模式的流式接口有额外限制. 响应选用小状态机的原因是固定标记语法更容易控制边界, 并不表示 AC 无法处理流式.

参考实现的核验结论:

| 项目 | 可以借鉴 | 需要避开的边界 |
| --- | --- | --- |
| Magpie | 固定格式检测, pending 尾部, JSON 转义, 心跳与签名处理 | 自动生成别名不同于本方案固定 KV; 单 pending 事件不能直接覆盖任意交错流; 内部包不能作为公共 SDK 导入 |
| prompt-anonymizer | 未完成标记前缀检测与跨事件缓冲, 分片切点测试设计 | 只处理首个 choice 正文; EOF, 异常和工具参数支持不完整; 不照搬逐项递归替换 |

| LLM Guard | 非流式反向替换参考 | scanner 没有跨片状态, 逐 chunk 调用无法恢复被拆开的标记 |

## 10. 复杂度与资源边界

设 `N` 为一份请求中受保护文本的总字节数, `M` 为响应中所有实际处理文本的总字节数, `P` 为规则原文总长度, `Q` 为完整占位符总长度, `Z` 为实际替换次数, `S` 为并行逻辑文本流数. `Breq` 和 `Bresp` 分别为写出的替换和还原文本总长度.

| 部分 | 时间 | 空间说明 |
| --- | --- | --- |
| 规则加载和预编译 | 常规 AC 构建通常为 O(P) 量级, 具体取决于实现 | 规则文本 O(P + Q), 自动机结构另计; DFA 表可能带字符集因子 |
| 一份出站文本替换 | O(N + Z + Breq) | 输出缓冲及库临时数据; 当前候选会复制输入并收集 O(Z) 匹配结果 |
| 响应状态机恢复 | O(M + Bresp), Map 按期望查找成本计算 | 恢复器待定内容 O(S * L), 单次输出及事件调度缓冲另计 |
| 请求规则状态 | 获取共享指针 O(1) | 不复制词库, 不分配命中集合 |

多次实际出站尝试的请求成本按各尝试的输入, 匹配及输出量相加. 最终快照事件中的重复文本也计入 `M`, 不将实际重复处理量隐藏在复杂度表达中. 旧请求持有的旧规则快照会延迟回收, 全局峰值空间还取决于同时存活的规则版本.

哈希查找前需要读取标记内容, 这部分长度已经计入 `M`. 使用可变字节缓冲或 Builder 保持摊销线性处理, 不用不可变字符串反复拼接. 输出的原文可能比占位符更长, 因此输出长度必须计入时间与峰值内存预算.

O(S * L) 仅描述恢复器, 不包括现有 JSON/SSE 解码, 原请求体和日志聚合. 当前 relay 会缓存 SSE 事件用于最终日志, 整条请求仍可能有随响应量增长的内存占用. 事件队列还要限制待处理字节和数量, 不能仅限制候选长度就认为总空间有界.

本方案不记录命中集合, 无需按 KV 数量寻找记录与不记录的性能拐点. 反查使用共享 Map, 不逐块遍历全部 KV. 最终吞吐和内存需按词条数, 文本长度, `L`, 逻辑流数及并发量进行定向验证.

## 11. 拟验证与验收

以下是拟执行范围, 本次写文档没有执行这些测试. 实施和验证前仍需批准具体改动及命令范围. 不为本功能直接运行整个构建包装器, 以免同时安装前端依赖, 改静态产物和更新价格等无关数据.

原文匹配验证覆盖无匹配, 首尾匹配, 重复命中, 同起点长短原文, 交叉重叠, Unicode, 引号和反斜杠, 以及替换值包含其他原文时不递归处理. 使用实际第三方 matcher 检查返回区间及替换语义.

恢复器验证对每个完整标记枚举所有两段切点, 补充三段及不同片段长度. 覆盖左前缀和右后缀分别跨片, 一块多个标记, 标记前后普通文字, 未知标记, 无效字符, 候选达到 `L`, 结束时半个标记, 原文内含其他完整标记, 空反查 Map 和 UTF-8 文本. 验收要求无吞字, 无重复, 无递归还原, 无越界, 正常路径候选有界.

SSE 协议验证覆盖各客户端协议的正文, 多 choice, 多工具交错, content block, 完整结果快照, 心跳, 正常终止, 无终止 EOF, 错误和客户端取消. 按最终保护范围补充内层 JSON 转义, 签名保持及引用偏移检查. 断言解析后的聚合文字与同快照的非流式恢复结果一致, 并验证事件顺序和标识合法.

数据库验证使用隔离的 SQLite, MySQL 和 PostgreSQL 环境检查两个独立唯一约束, 精确比较语义, 并发创建, 冲突更新, 启用和删除行为, 幂等导入与冲突回滚. 不用 Mock 证明实际数据库 collation 或索引行为.

并发验证在后台更新格式和规则时持续发送请求, 确认单个请求不会混用新旧 Map 或 `L`, AC 与恢复器无共享可变解析状态, 已返回流不会被提前清理. 验证快照版本与流关闭后的资源回收.

集成验证保留分组优先, 指定渠道直连单次尝试, 受限 API Key, 请求选项覆盖顺序, 熔断和写回后停止重试. 通过独立本地上游记录实际 HTTP 内容校准, 断言选定字段已替换, 结构和认证信息未误改. 本地上游仅用于协议与逻辑校准; 经单独授权后再用真实上游和隔离数据验证模型保留标记的情况.

性能验证区分冷编译与热请求, 有无匹配, 少量与大量规则, 长原文, 短 SSE delta 和高并发. 测量输入复制, 匹配列表, 每个逻辑流缓冲, 快照更新与 WASM 资源释放. 不预设某个 KV 数量就是实现优劣反转点.

## 12. 实施前待确认事项

1. 最终 LEFT/RIGHT 字面值, 别名字符集与长度, 原文长度, 以及前后缀是否允许运行时修改.

5. 请求和响应日志正文的原文保留策略, 规则备份的敏感数据提示和管理界面展示方式.
